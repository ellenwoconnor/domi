# Domi

Domi is a mobile-first app for giving away items for free within local and custom communities, called **circles**. It is a rebuild of an earlier web app, Corcles. Goal for launch: one thriving invite-driven circle, running for about $35/month, built by one developer.

Full product and data details: @docs/spec.md
Milestones and what "done" means for each: @docs/build-plan.md
Vendors, public IDs, secrets, and costs: `docs/vendors.md`

## Stack

- App: Expo SDK 57 (React Native; pinned to the SDK the installed Expo Go supports), TypeScript (strict), Expo Router, TanStack Query (wired to Convex via `@convex-dev/react-query`)
- Backend: Convex (database, queries/mutations/actions, live queries, file storage, scheduler, cron jobs)
- Auth: Convex Auth (`@convex-dev/auth`, beta) with native sign-in. The app gets an ID token from Apple's sheet (`expo-apple-authentication`) or Google's (`@react-native-google-signin/google-signin`) and calls `signIn("apple"|"google", { idToken, ... })`; `convex/auth.ts` verifies it (`convex/lib/idTokens.ts`, tested) and finds or creates the account. Session tokens are stored in SecureStore. Fallback if this proves unreliable: Clerk + Convex.
- UI: follows "Domi Circles — Brand Strategy" (Neighborhood Modern on white, Fog & Poppy). Tokens in `src/ui/theme.ts`: Bay Blue #1F4E79 primary, Poppy #F2652B for giving moments only (text on Poppy is Ink), Fog/Blush tints. Fraunces Italic for headlines and captions, Figtree for UI (`@expo-google-fonts/*`, loaded in `app/_layout.tsx`). Logo is the "o" ring mark (`src/ui/Logo.tsx`). Icons: `@expo/vector-icons` (Ionicons). No red badges, no bright blue, no eco clichés.
- Photos: `expo-image-picker` (camera/library) + `expo-image-manipulator` (compression), uploaded to Convex file storage
- Push: Expo push service via `expo-notifications`, sent from a Convex action
- Builds: EAS Build / Submit / Update
- Website: `web/`, a Cloudflare Worker on domicircles.com serving the app-link files and the invite (`/c/<code>`) and shared-listing (`/i/<code>`) pages, with link previews
- No custom API server. The app calls Convex functions directly; authorization is enforced inside those functions.

`docs/spec.md` is written for Convex (translated from the original Supabase spec on 2026-10-21; the "spec.md" Google Doc is the older source). Unique/partial-unique constraints are checks inside the mutation that writes the row.

## Repo layout

- `app/` Expo Router screens (`_layout.tsx` = navigators). Keep non-route code out of `app/`.
- `src/features/<feature>/` hooks, components, and queries per feature (auth, circles, items, threads, activity)
- `src/ui/` shared design tokens and primitives (Logo, CircleMark, PhotoTile, FreeDot)
- `src/lib/convex.ts` the single Convex client + TanStack QueryClient
- Navigation: tabs Browse · Give · Activity · You (`app/(tabs)/`). You = profile row + my circles (later my listings and requests). Invite and share links open `app/c/[code].tsx` and `app/i/[code].tsx` in every sign-in state.
- `convex/schema.ts` the schema; `convex/<module>.ts` functions; `convex/<module>.test.ts` tests
- `convex/_generated/` generated by the Convex CLI; never edit by hand, do commit it
- `convex/init.ts` idempotent seed, run on every `npm run dev:backend` (appConfig incl. `terms_version`, a few dev zip codes)
- `convex/lib/` shared helpers: `access.ts` (access checks), `lifecycle.ts` (item/request state changes + events), `circles.ts` (join/leave cleanup), `redeem.ts` (invite/share codes); `testing.helpers.ts` is test-only (double dot keeps it out of deploys)

## Commands

Keep this list accurate.

- Install: `npm install`
- Backend (dev deployment, watches `convex/`, regenerates types, runs `init`): `npm run dev:backend`
- Start app: `npm start` (opens in the Domi development build, not Expo Go)
- Build the development app on Expo's servers (needed after adding native libraries): `npm run build:dev:ios`
- One-time auth key setup per Convex deployment: `npm run setup:auth`
- Run a function by hand: `npx convex run <module>:<fn> '{"arg": 1}'`
- Open the Convex dashboard (data browser, logs): `npx convex dashboard`
- Tests: `npm test`
- Dev-only password sign-in on the dev deployment (never prod): `npx convex env set DEV_PASSWORD_AUTH true`
- Load the full US zip table: see `scripts/import-zips.mjs` (download GeoNames US.zip, convert, `npx convex import --table zipCodes`)
- Typecheck (app + convex): `npm run typecheck`
- Website tests: `npm run test:web`; deploy: `cd web && npx wrangler deploy` (see `web/README.md`)
- Add an Expo/RN package: `npx expo install <pkg>` (picks SDK-compatible versions)

## Access checks (replaces RLS)

- Every public `query`/`mutation`/`action` starts by resolving the caller (`ctx.auth.getUserIdentity()` → profile) and checking access per the "Access rules" section of `docs/spec.md`. No exceptions; put shared checks in helpers in `convex/lib/`.
- Functions that only the system should call (seeding, cron work, push sending) are `internalQuery`/`internalMutation`/`internalAction`.
- Multi-step flows (signup, invite redemption, wishlist fulfillment, zip change, picking a recipient) are each one mutation, so they run in one transaction.
- Validate all args with `v.*` validators. Never trust a user id passed from the client; derive it from auth.
- Every table with access rules gets `convex-test` tests that prove both the allowed and the denied cases.

## Rules

- Schema changes go in `convex/schema.ts`. If a change would invalidate existing data, write a migration (widen the schema, backfill, then narrow) rather than breaking the deployment.
- Never put a secret in app code or in git. App code only uses `EXPO_PUBLIC_*` vars, which ship in the app. Server secrets live in Convex environment variables (`npx convex env set`).
- Every message, request, or item state change writes one row to `events`, in the same mutation. Push and the Activity tab both read from `events`; never send a push from anywhere else.
- Each event row names its recipient and its own copy. Never send the same copy to both owner and asker.
- Exact addresses are never stored on items or shown in feeds. Listings show an approximate area only.
- Keep scope to the MVP in `docs/spec.md`. If a task seems to need an out-of-scope feature (payments, bidding, karma, calendar scheduling), stop and ask.
- Prefer built-in Convex/Expo features over new vendors or libraries. Ask before adding a dependency that isn't in the stack above.
- Expo changes between SDKs; check the docs for SDK 57 rather than relying on memory. The app runs in a development build (`expo-dev-client`) built on EAS, because native sign-in needs native code and the dev Mac (macOS 14) can't build iOS locally. Adding a library with native code means a new `npm run build:dev:ios`.
- Use "circle" in all user-facing copy. Use `communities` in the database.

## How to work

- Work one milestone from `docs/build-plan.md` at a time. Plan first, then build, then verify against that milestone's done criteria.
- After a change: typecheck, run tests, and say how you verified it.
- Commit after each working step with a clear message.

## Design mockup

The Browse (Free / Wishes), item detail, Give, wish fulfillment and Activity screens currently run on mock data (`src/features/items/mockData.ts`, `src/features/wishlist/store.ts`, `src/features/activity/mockEvents.ts`). Replace the mocks with Convex queries in the milestone that builds each feature (M3 items, M4 requests, M5 activity); keep the visual design.

Wishlist UX (mockup decisions): wishes live on Browse as a second view ("Free" / "Wishes"), share the search and circle filter, and show "My wishes" at the top. "I have this" is a quiet Blush pill with the Poppy dot; solid Poppy is saved for "Send to <name>". The Give tab shows a "Your circles are looking for" strip. Fulfillment flow: photo, details, send (a private offer). Decided 2026-10-21: offers accumulate and the wisher picks one, which opens the chat; the wish stays visible to others until it's fulfilled (see "Wish offers" in `docs/spec.md`).
